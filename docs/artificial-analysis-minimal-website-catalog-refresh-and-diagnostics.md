# D-12：最小化网页目录刷新与异常诊断

本实现承接 ca0af 的离线解析、逐 UUID 当期判定与 API 缓存护栏。用户在 fc98a 会话选择：方案获批后恢复受限自动刷新；最多每 24 小时一批；失败复用已验证旧目录；连续封禁或结构变化只启动一个诊断 Task；未 resolve 时新生成开发页持续告警；旧 HTML 原位保留并另做持久备份。产品 HTML 的内嵌数据精简调查已按用户要求拆到 d4957，不属于本卡改造范围。

## 刷新策略与数据边界

- 默认不联网读取目录；`--refresh` 刷新 API，并在网页冷却期结束后采集目录。`--allow-artificial-analysis-website-page-fetch` 显式请求目录刷新；`--disable-artificial-analysis-website-page-fetch` 禁止本次网页请求，两个开关互斥。
- 每批选择最新发布、有 API 智能分且 slug 有效的详情页，第二页优先不同厂商。通常两页；请求失败、目录不足或 API UUID 未覆盖时最多三页。不会逐模型补抓缺 token 的详情页，也不会请求 `/models` 列表页。
- UA 明确标识 `ai-analysis-frontier-3d/0.1.0`。串行页间至少 10 秒，暂时性错误最多重试一次、等待 30 秒；TLS 错误可回退系统 curl 一次。重试和回退共用每批六次 HTTP 尝试上限；单次 30 秒、页面 12 MiB 上限，不跟随重定向，不关闭 TLS 校验。
- 403、429、验证挑战立即中止本批，不换页绕过限制。失败也占用 24 小时冷却期，更长的 `Retry-After` 会推迟下一次允许时间。
- HTML 只在内存中解析，不写入新 HTML 文件。数值响应包含现有解析字段、版本、时间、来源页摘要和批次标识；不保存整份 RSC 或页面状态。

同一客户端采集批次不等于服务器承诺的原子快照。新批次要求至少两页完整、精确页面版本一致、与 API 版本 family 一致；同 UUID 字段冲突直接拒绝本批。带 token 的 API UUID 交集至少 50 条；同 family 相较上一份有效目录覆盖骤降超过 30% 时拒绝。整体智能分一致率仍只告警，token 是否当期继续逐 UUID 以智能分容差 0.05 判定，没有恢复整体 ≥99% 拒绝逻辑。

API 与目录共用唯一暂存及原子文件写入函数。目录先写带待校验标记的暂存与响应历史，最终数据护栏通过才晋升；拒绝保留诊断历史、清理暂存、保持原有效缓存。API 历史既有命名和基线识别保持兼容。每个文件原子替换，不宣称 API 和目录两个文件能一起原子提交。

## 连续异常与诊断 Task

健康状态按 canonical 主仓库路径隔离，跨工作树共用锁与持久事件。默认位于 `~/.cline/kanban/cross-task-handoff-artifacts/artificial-analysis-website-catalog-refresh/<主仓库路径哈希>/project-refresh-health-state/`，不会随进程退出、普通重启或任务 worktree 清理而消失。

成功验证的数值目录同时发布为项目级不可变副本，按内容 SHA256 索引。其他工作树在冷却期内可复用这份目录，仍需与各自 API 数据一起通过最终护栏；无需重复请求网页。复用副本不等于重新验证网站，不清除已有异常事件。

封禁或结构变化首次出现时生成事件 ID、持久保存脱敏状态与结构摘要，并创建、启动 `[RESEARCH]诊断 AA 网页目录刷新异常`。后续同一连续故障只更新证据；失败类别变化也不重复建卡。Task 继承实际默认启动设置，Prompt 明确只读分析，不额外请求 AA 网页、不自动修复。

结构摘要只包含有限字段名、类型和计数，不包含模型值或 RSC 原文。首次故障还保存生成器源码快照，避免诊断 Task 从尚未合入实现的 main 启动后分析错代码版本。

创建调用的结果不确定时只按持久事件标识回查，禁止重放 create；启动失败只重试已创建的同一 Task。不能可靠确认创建结果时显示待核对，不能承诺无证据的“已启动”。CLI 不可用不阻断 API 与旧目录降级。只有新目录完整通过护栏且晋升后才 resolve；读取缓存、冷却跳过、关闭诊断卡均不算恢复。恢复后再次异常使用新事件 ID。

可覆盖的运行配置：

- `ARTIFICIAL_ANALYSIS_CATALOG_REFRESH_HEALTH_DIRECTORY`：健康状态与诊断材料的持久根目录；测试必须使用隔离位置。
- `ARTIFICIAL_ANALYSIS_DIAGNOSTIC_KANBAN_COMMAND_JSON`：Kanban 命令的 JSON 参数数组。默认使用本机已知 Node v24.12.0 与 Kanban 安装；不可用时记录待派发，不调用同名的其他程序。

## 开发告警与正式部署

所有自包含 HTML 渲染入口默认是 `development`。渲染时读取项目当前未恢复事件，因此已有契约重渲染也会显示告警；不只依赖旧契约里保存的某次状态。告警显示故障、首次时间、当前目录日期、诊断 Task 及启动状态，按纯文本转义并使用 `role="alert"`。

`--report-deployment-environment production` 只隐藏开发诊断标记，不隐藏目录来源、真实数据日期和已有数据质量告警。一键入口转发相同选项。旧 HTML 不会被后台改写；恢复只影响之后新生成的页面。
